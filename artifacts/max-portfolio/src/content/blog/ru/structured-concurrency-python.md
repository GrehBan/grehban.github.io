Ошибки конкурентности часто начинаются с работы, у которой нет явного
владельца. Обработчик запроса создаёт задачу, задача переживает запрос, а при
завершении приложения её уже не удаётся надёжно найти. Структурная
конкурентность решает эту проблему: дочерняя работа живёт внутри явной области
выполнения.

## У каждой задачи есть родитель

`asyncio.TaskGroup` показывает, что несколько операций относятся к одной
единице работы. Если одна задача завершается с ошибкой, соседние отменяются,
а группа дожидается их завершения перед выходом из блока.

```python
async with asyncio.TaskGroup() as group:
    profile = group.create_task(fetch_profile(user_id))
    preferences = group.create_task(fetch_preferences(user_id))

return profile.result(), preferences.result()
```

Теперь структура кода описывает время жизни обеих операций. Они не смогут
незаметно продолжиться после того, как вызывающая сторона уже завершила работу.

## Считайте отмену обычным управлением потоком

Отмена сообщает, что работа больше не нужна: например, из-за таймаута,
отключения клиента или остановки приложения. Освобождение ресурсов следует
выполнять в блоках `finally`, а `CancelledError` обычно нужно повторно выбрасывать
после очистки, а не подавлять.

Это особенно важно для сетевых вызовов и потоковых ответов: своевременное
закрытие ответа освобождает сокеты и прекращает работу, результат которой уже
не будет использован.

## Ограничивайте нагрузку на входе

Структурированное время жизни задач само по себе не ограничивает конкуренцию.
Если сервис может получить больше работы, чем обработать, сочетайте явное
владение задачами с ограниченными очередями, семафорами или пулами воркеров.

Цель не в том, чтобы сделать асинхронный код абстрактным. Нужно сделать время
жизни задач, ошибки и отмену достаточно явными, чтобы сервис предсказуемо
завершался.
